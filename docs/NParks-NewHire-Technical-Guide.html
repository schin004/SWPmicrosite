1 · Overview & design goals

The portal is a single-file, server-rendered Node/Express web app. Every page is HTML rendered on the server; forms submit with a normal page reload. A little inline JavaScript adds niceties (photo preview, word counter, the canvas photo editor, the "Save as PNG" export) but nothing essential depends on client-side JS — important because it must work inside locked-down government browsers.

Design goals that shaped it:

  • One file, no build step. The whole app is server.js. There is no bundler, framework or compile step to maintain — you deploy the file as-is. (Rationale: survivability and easy hand-over.)
  • Deliverable by copy-paste. The NParks network blocks file downloads, so the file is handed over as pasted text and saved locally. Keeping it to one file makes that practical.
  • Resilient boot. The web server starts listening immediately; database setup runs in the background and retries, so a slow database never takes the site down.
  • Two-factor everywhere. Both the new-hire form and the HR console require a shared password and an emailed one-time code.
Two editions in the repo. The deployed app is the single-file greenpass-rabbit/server.js. The repository also contains a parallel React + Vite + Express edition at the root (server.js, src/) kept roughly in sync for reference. If in doubt, the single-file edition is the source of truth for what is live.

3 · Deployment (Rabbit)

  1. Upload server.js and package.json to the Rabbit service.
  2. Create/attach a PostgreSQL database — Rabbit sets DATABASE_URL automatically. The app creates its own tables on first run (ensureSchema()), so there is no migration step to run.
  3. Set the environment variables (next section). At minimum set the two passwords, the OTP send URL + key, ADMIN_EMAILS and SESSION_SECRET.
  4. Deploy. Rabbit runs npm install then npm start (node server.js).
Photos are stored in the database (as bytea), never on disk — so redeploys and container restarts never lose data. Everything persistent lives in Postgres.
Delivery note: because downloads are blocked on the NParks network, the file is updated by pasting its full contents into a text editor, saving as server.js, and uploading. Keep changes in one file to preserve this workflow.

6 · Authentication & the OTP flow

Two roles, two cookies. A verified new hire holds a gp_joiner cookie; a verified HR officer holds gp_admin. Both are short, HMAC-SHA256-signed tokens (see signToken/verifyToken) carrying the role, the verified email, and an expiry. There is no server-side session store — the signature is the proof.

The code is generated and verified by the app itself — the external service (Postman) only delivers the email. This matters: Postman is a send-only service and cannot check codes. The flow:

  1. User passes the password + enters their email.
  2. issueOtp() generates a random 6-digit code, asks the sender to email it, and returns a salted hash of the code.
  3. That hash (not the code) is stored in a short-lived signed "pending" cookie (gp_j_pending / gp_a_pending), along with the email and an attempt counter.
  4. On submit, checkOtp() re-hashes what the user typed and compares with a constant-time check. Correct → the real session cookie is issued. Wrong → attempt counter increments; after OTP_MAX_ATTEMPTS the pending cookie is cleared and they start again.
Why hash the code in the cookie? Cookie contents are readable by the browser, so the plain code must never be put there. The salted HMAC can't be reversed or forged without SESSION_SECRET, and nothing about the code touches the database — so it works across restarts and multiple instances with no shared state.
Safe fallback: if OTP_SEND_URL is unset, otpEnabled is false and the password alone signs the user in — nobody is locked out while the sender is being configured.

Admin allow-list: HR login additionally checks the email against ADMIN_EMAILS before sending a code. New hires may use any email.

Identity binding (important): a signed-in new hire can only read or edit the submission tied to their own verified email. The /submit and /amend handlers use joinerEmail(req) from the session — never an email from the form body — and /api/photo/:id only serves a photo to an admin or to the owning joiner.

7 · Submission lifecycle

awaiting-hr-review— Approve → approved— Archive → archived
  • awaiting-hr-review — just submitted (or amended). New hires may still self-amend.
  • approved — HR has added job details and approved; appears in "Generate eDM".
  • archived — welcome email already sent; kept on record, excluded from new eDMs.
  • rejected — not included in any eDM; can be restored to review.

Re-submitting under the same email updates the existing non-approved row in place (the app matches by email). Approved rows are never silently overwritten.

9 · Security measures (please don't regress these)

The app was hardened against a specific set of findings. If you refactor, keep these intact:

  1. Identity binding. Submission read/write is keyed to the session's verified email (joinerEmail(req)), never a form field — prevents one joiner editing another's entry.
  2. Secure cookies. Session & OTP cookies are HttpOnly; Secure; SameSite=Lax (Secure toggled only by COOKIE_SECURE=0 for local tests).
  3. Photo authorization. /api/photo/:id serves a photo only to an admin or the owning joiner; otherwise 404. Cache is private, no-store.
  4. Security headers. HSTS, CSP (locks scripts/styles/images/forms to same-origin), X-Frame-Options, X-Content-Type-Options, Referrer-Policy, COOP; x-powered-by disabled.
  5. Upload sniffing. Uploads are validated by magic bytes and only the real MIME is stored — a spoofed Content-Type is rejected.
  6. DB TLS verification on by default. rejectUnauthorized:true unless a CA is pinned or explicitly opted out.
Never reintroduce a hardcoded rejectUnauthorized:false, trust a form-supplied email for authorization, or serve /api/photo without the owner/admin check.

10 · eDM generation logic

buildEdmHtml(hires, occasion, sendDate) produces an Outlook-safe email: 100% table-based layout, all CSS inline, images embedded as base64 data: URIs (so nothing is fetched when the email is opened), a fixed WIDTH (1120px) single wide column with one "spotlight" card per new hire, and an MSO "ghost table" + transparent-GIF spacer so Outlook holds the width. Joiners are grouped into fortnights by periodOf() for the "quick-select by period" buttons. Each generated eDM's HTML is saved to edm_archive.

If you change the eDM design, keep it table-based with inline styles and embedded images — modern CSS (flexbox, grid, external stylesheets, web fonts) is unreliable in Outlook. Test by sending a real message to an Outlook inbox, not just the in-app preview.

12 · Local development & testing

  1. cd greenpass-rabbit && npm install.
  2. Run a local Postgres and export DATABASE_URL=postgres://… with PGSSL=disable and COOKIE_SECURE=0.
  3. For the full two-factor flow locally, point OTP_SEND_URL at a tiny mock HTTP server that records the code from the request body; or leave it unset to sign in with password only.
  4. SEED_DEMO=1 npm start, then open http://localhost:3000.

The project was validated with scripted end-to-end checks driving the real HTTP endpoints (joiner + admin login, wrong-code lockout, resend-invalidates-old, photo ownership 404s, upload sniffing, and the security headers/cookies). When changing auth, DB or upload code, re-run equivalent checks before shipping.

13 · Constraints & gotchas

  • Downloads are blocked on the NParks network. Update the app by pasting the full file; keep everything in the single file.
  • Postman is send-only. It delivers the code email; the app must generate and verify codes itself. Don't look for a "verify" endpoint.
  • Managed Postgres closes idle connections. The pool's error handler swallows that; don't remove it or the process can crash.
  • Boot order matters. app.listen() runs before schema setup on purpose. Keep schema/seed in the background .then()/.catch() so a slow DB can't block startup (this was the fix for an earlier "upstream timeout").
  • CSP uses 'unsafe-inline' for scripts/styles because the pages rely on inline handlers and styles. If you move to external/nonce'd assets you can tighten it.

// Constant-time check of the submitted code against the hash in the pending cookie.
function checkOtp(pend, submitted) {
  if (!pend || !pend.codeHash) return false;
  const h = hashCode(pend.email, submitted);
  try { return crypto.timingSafeEqual(Buffer.from(h), Buffer.from(pend.codeHash)); } catch { return false; }
}

function verifyToken(token) {
  if (!token || token.indexOf('.') < 0) return null;
  const [p, sig] = token.split('.');
  const expect = b64u(crypto.createHmac('sha256', SESSION_SECRET).update(p).digest());
  if (!sig || sig.length !== expect.length || !crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expect))) return null;
  try { const d = JSON.parse(b64uDec(p)); return (d && d.exp && d.exp > Date.now()) ? d : null; } catch { return null; }
}

// Bucket a joining date into a fortnight period: the 1st–15th (H1) or the
// 16th–end (H2) of its month. Used to generate one eDM per half-month.
const MONTHS = ['January', 'February', 'March', 'April', 'May', 'June', 'July', 'August', 'September', 'October', 'November', 'December'];
function periodOf(start_date) {
  const m = /^(\d{4})-(\d{2})-(\d{2})/.exec(String(start_date || ''));
  if (!m) return null;
  const y = +m[1], mo = +m[2], d = +m[3];
  const h1 = d <= 15;
  const lastDay = new Date(y, mo, 0).getDate();
  return {
    key: `${m[1]}-${m[2]}-${h1 ? 'H1' : 'H2'}`,
    sort: `${m[1]}${m[2]}${h1 ? '1' : '2'}`,
    label: `${h1 ? '1–15' : '16–' + lastDay} ${MONTHS[mo - 1]} ${y}`,
  };
}

async function moderateText(text) {
  const key = process.env.ANTHROPIC_API_KEY;
  if (!key) return { status: 'review', confidence: 0, reason: 'AI moderation is unavailable (no ANTHROPIC_API_KEY configured) — please review this introduction manually.' };
  try {
    const res = await fetch('https://api.anthropic.com/v1/messages', {
      method: 'POST',
      headers: { 'content-type': 'application/json', 'x-api-key': key, 'anthropic-version': '2023-06-01' },
      body: JSON.stringify({ model: 'claude-3-5-haiku-20241022', max_tokens: 300, system: MODERATION_SYSTEM_PROMPT, messages: [{ role: 'user', content: text }] }),
    });
    if (!res.ok) throw new Error(`Claude API returned ${res.status}`);
    const data = await res.json();
    const raw = (data.content || []).map((b) => b.text || '').join('').trim();
    const match = raw.match(/\{[\s\S]*\}/);
    const parsed = JSON.parse(match ? match[0] : raw);
    const status = ['clear', 'review', 'flagged'].includes(parsed.status) ? parsed.status : 'review';
    return { status, confidence: Math.max(0, Math.min(100, Number(parsed.confidence) || 0)), reason: String(parsed.reason || 'No explanation provided.') };
  } catch (err) {
    console.warn('[moderation] fallback:', err.message);
    return { status: 'review', confidence: 0, reason: 'AI moderation could not be completed automatically — please review this introduction manually.' };
  }
}

// ── Photo dimension check (PNG + JPEG, no dependencies) ───────────────────────
function readImageDimensions(buffer) {
  if (buffer.length > 24 && buffer.readUInt32BE(0) === 0x89504e47) return { width: buffer.readUInt32BE(16), height: buffer.readUInt32BE(20) };
  if (buffer.length > 4 && buffer[0] === 0xff && buffer[1] === 0xd8) {
    let o = 2;
    while (o < buffer.length) {
      if (buffer[o] !== 0xff) { o++; continue; }
      const marker = buffer[o + 1];
      if (marker >= 0xc0 && marker <= 0xcf && ![0xc4, 0xc8, 0xcc].includes(marker)) return { height: buffer.readUInt16BE(o + 5), width: buffer.readUInt16BE(o + 7) };
      o += 2 + buffer.readUInt16BE(o + 2);
    }
  }
  return null;
}
function checkPhoto(buffer) {
  try {
    if (buffer.length > 5 * 1024 * 1024) return { status: 'manual-review', reason: 'Photo exceeds the 5MB limit — please verify.' };
    const dim = readImageDimensions(buffer);
    if (!dim) return { status: 'manual-review', reason: 'Could not read image dimensions — please visually verify the photo before approving.' };
    if (dim.width < 100 || dim.height < 100) return { status: 'manual-review', reason: `Photo is only ${dim.width}x${dim.height}px (below 100x100) — please verify quality.` };
    return { status: 'manual-review', reason: `Photo is a valid ${dim.width}x${dim.height}px image. Please visually verify it is appropriate before approving.` };
  } catch { return { status: 'manual-review', reason: 'Photo could not be inspected — please visually verify before approving.' }; }
}

// Verify a buffer really is a JPEG or PNG by its magic bytes — the client-sent
// Content-Type is trivially spoofable and must never be trusted. Returns the
// real MIME type, or null if the bytes are not an accepted image.
function sniffImageType(buf) {
  if (!buf || buf.length < 4) return null;
  if (buf[0] === 0x89 && buf[1] === 0x50 && buf[2] === 0x4e && buf[3] === 0x47) return 'image/png';  // \x89PNG
  if (buf[0] === 0xff && buf[1] === 0xd8 && buf[2] === 0xff) return 'image/jpeg';                    // JPEG SOI
  return null;
}

app.post('/submit', (req, res) => {
  if (!hasJoiner(req)) return res.send(joinerGatePage({ error: 'Please sign in with the access password and a one-time code first.', next: '/submit' }));

    // Identity is the OTP-verified email in the session — NEVER an email posted
    // in the form. This stops a signed-in joiner from reading or amending anyone
    // else's submission by typing a different address.
    const mail = (joinerEmail(req) || '').trim();
    // Re-render the form with an error message.
    const fail = async (message, status = 400) => {
      let photoUrl = null;
      if (pool && mail) {
        const ex = await pool.query("select id from submissions where lower(email)=lower($1) and status <> 'approved' order by created_at desc limit 1", [mail]);
        photoUrl = ex.rows.length ? `/api/photo/${ex.rows[0].id}` : null;
      }
      return res.status(status).send(submitPage({ error: message, values: { ...req.body, email: mail }, amend, photoUrl }));
    };

    if (err) return fail(err.message);
    if (!pool) return fail('Database is not configured yet. Please try again shortly.', 503);
    const { full_name, intro, fun_fact } = req.body;
    if (!full_name || !intro) return fail('Full name and introduction are both required.');
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(mail)) return fail('Your session is missing a valid email. Please sign in again.');

    try {
      const name = full_name.trim();

      // Find THIS joiner's existing entry (their own session email) that HR has
      // NOT yet approved. If found, we UPDATE it in place — a photo is optional
      // here (leave it out to keep the current one). If not found, this is a
      // brand-new submission and a photo is required. Approved entries untouched.
      const existing = await pool.query(
        `select id from submissions where lower(email) = lower($1) and status <> 'approved'
         order by created_at desc limit 1`, [mail]);
      const isEdit = existing.rows.length > 0;
      if (!req.file && !isEdit) return fail('A profile photo is required.');

      // Authoritative image check: trust the bytes, not the client Content-Type.
      let photoMime = null;
      if (req.file) {
        photoMime = sniffImageType(req.file.buffer);
        if (!photoMime) return fail('That file is not a valid JPG or PNG image. Please upload a real photo.');
      }

      const ai = await moderateText(intro);
      const photo = req.file ? checkPhoto(req.file.buffer) : null;

      if (isEdit) {
        if (req.file) {
          await pool.query(
            `update submissions set full_name=$1, email=$2, intro=$3, fun_fact=$4, status='awaiting-hr-review',
               ai_status=$5, ai_confidence=$6, ai_reason=$7, photo_status=$8, photo_reason=$9,
               photo_mime=$10, photo_data=$11, orig_photo_mime=null, orig_photo_data=null, updated_at=now() where id=$12`,
            [name, mail, intro.trim(), (fun_fact || '').trim() || null, ai.status, ai.confidence, ai.reason,
             photo.status, photo.reason, photoMime, req.file.buffer, existing.rows[0].id],
          );
        } else {
          // No new photo — keep the existing one, update everything else.
          await pool.query(
            `update submissions set full_name=$1, email=$2, intro=$3, fun_fact=$4, status='awaiting-hr-review',
               ai_status=$5, ai_confidence=$6, ai_reason=$7, updated_at=now() where id=$8`,
            [name, mail, intro.trim(), (fun_fact || '').trim() || null, ai.status, ai.confidence, ai.reason, existing.rows[0].id],
          );
        }
        return res.redirect(`/submit/thanks?name=${encodeURIComponent(name)}&updated=1`);
      }

      const { rows } = await pool.query(
        `insert into submissions (full_name,email,intro,fun_fact,status,ai_status,ai_confidence,ai_reason,photo_status,photo_reason,photo_mime,photo_data)
         values ($1,$2,$3,$4,'awaiting-hr-review',$5,$6,$7,$8,$9,$10,$11) returning full_name`,
        [name, mail, intro.trim(), (fun_fact || '').trim() || null, ai.status, ai.confidence, ai.reason, photo.status, photo.reason, photoMime, req.file.buffer],
      );
      res.redirect(`/submit/thanks?name=${encodeURIComponent(rows[0].full_name)}`);
    } catch (e) {
      console.error(e);
      return fail('Something went wrong saving your submission. Please try again.', 500);
    }
  });
});

// ── Admin: update (save / approve / reject / restore / edit) ─────────────────
app.post(ADMIN_PATH + '/update', async (req, res) => {
  if (!hasAdmin(req)) return res.send(adminLoginPage());
  if (!pool) return res.redirect(ADMIN_PATH + '?err=' + encodeURIComponent('No database connected.'));
  const { id, action } = req.body;
  try {
    const { rows } = await pool.query('select job_title,division from submissions where id=$1', [id]);
    if (!rows.length) return res.redirect(ADMIN_PATH + '?err=' + encodeURIComponent('Submission not found.'));
    const cur = rows[0];

    if (action === 'reject') {
      await pool.query('update submissions set status=$1,updated_at=now() where id=$2', ['rejected', id]);
      return res.redirect(ADMIN_PATH + '?msg=' + encodeURIComponent('Entry rejected.'));
    }
    if (action === 'restore') {
      await pool.query('update submissions set status=$1,updated_at=now() where id=$2', ['awaiting-hr-review', id]);
      return res.redirect(ADMIN_PATH + '?msg=' + encodeURIComponent('Entry restored to review.'));
    }
    if (action === 'archive') {
      await pool.query("update submissions set status='archived',updated_at=now() where id=$1 and status='approved'", [id]);
      return res.redirect(ADMIN_PATH + '?msg=' + encodeURIComponent('Entry archived — it stays on record but won\'t appear when generating new eDMs.'));
    }
    if (action === 'unarchive') {
      await pool.query("update submissions set status='approved',updated_at=now() where id=$1 and status='archived'", [id]);
      return res.redirect(ADMIN_PATH + '?msg=' + encodeURIComponent('Entry restored to Approved.'));
    }
    if (action === 'revert-photo') {
      // Restore the joiner's original photo and clear the snapshot (current == original again).
      const { rowCount } = await pool.query(
        `update submissions set photo_mime=orig_photo_mime, photo_data=orig_photo_data,
           photo_status='manual-review', photo_reason='Reverted to the joiner''s original submitted photo — please verify before approving.',
           orig_photo_mime=null, orig_photo_data=null, updated_at=now()
         where id=$1 and orig_photo_data is not null`, [id]);
      return res.redirect(ADMIN_PATH + '?msg=' + encodeURIComponent(rowCount ? 'Photo reverted to the joiner\'s original.' : 'There is no original photo to revert to.'));
    }
    if (action === 'edit') {
      await pool.query('update submissions set full_name=$1,email=$2,intro=$3,fun_fact=$4,updated_at=now() where id=$5',
        [(req.body.full_name || '').trim(), (req.body.email || '').trim() || null, (req.body.intro || '').trim(), (req.body.fun_fact || '').trim() || null, id]);
      return res.redirect(ADMIN_PATH + '?msg=' + encodeURIComponent('Details updated.'));
    }
    // save or approve → persist HR fields (job title, division, start date)
    const jobTitle = (req.body.job_title || '').trim();
    const division = (req.body.division || '').trim();
    const startDate = (req.body.start_date || '').trim();
    if (action === 'approve' && (!jobTitle || !division || !startDate)) {
      return res.redirect(ADMIN_PATH + '?err=' + encodeURIComponent('Job Title, Division and Start Date must all be filled in before approving.'));
    }
    const status = action === 'approve' ? 'approved' : undefined;
    if (status) await pool.query('update submissions set job_title=$1,division=$2,start_date=$3,status=$4,updated_at=now() where id=$5', [jobTitle, division, startDate || null, status, id]);
    else await pool.query('update submissions set job_title=$1,division=$2,start_date=$3,updated_at=now() where id=$4', [jobTitle, division, startDate || null, id]);
    res.redirect(ADMIN_PATH + '?msg=' + encodeURIComponent(action === 'approve' ? `Approved — ${jobTitle}, ${division}.` : 'HR details saved.'));
  } catch (e) {
    console.error(e);
    res.redirect(ADMIN_PATH + '?err=' + encodeURIComponent('Update failed. Please try again.'));
  }
});

app.post(ADMIN_PATH + '/photo', (req, res) => {
  upload.single('photo')(req, res, async (err) => {
    if (!hasAdmin(req)) return res.status(403).json({ error: 'Not authorised.' });
    if (!pool) return res.status(503).json({ error: 'No database connected.' });
    if (err) return res.status(400).json({ error: err.message });
    const { id } = req.body;
    if (!id) return res.status(400).json({ error: 'Missing submission id.' });
    if (!req.file) return res.status(400).json({ error: 'No image was received.' });
    // Trust the bytes, not the client Content-Type.
    const photoMime = sniffImageType(req.file.buffer);
    if (!photoMime) return res.status(400).json({ error: 'That file is not a valid JPG or PNG image.' });
    try {
      const photo = checkPhoto(req.file.buffer);
      // Keep a one-time snapshot of the joiner's original photo (coalesce: only
      // fills orig_* the first time HR edits) so it can be reverted later.
      const { rowCount } = await pool.query(
        `update submissions set
           orig_photo_mime = coalesce(orig_photo_mime, photo_mime),
           orig_photo_data = coalesce(orig_photo_data, photo_data),
           photo_mime=$1, photo_data=$2, photo_status=$3, photo_reason=$4, updated_at=now()
         where id=$5`,
        [photoMime, req.file.buffer, photo.status, photo.reason, id]);
      if (!rowCount) return res.status(404).json({ error: 'Submission not found.' });
      res.json({ ok: true });
    } catch (e) {
      console.error(e);
      res.status(500).json({ error: 'Could not save the photo. Please try again.' });
    }
  });
});

// ── Demo seed (solid-colour avatar PNGs, no dependencies) ────────────────────
function crc32(buf) { let c = ~0; for (let i = 0; i < buf.length; i++) { c ^= buf[i]; for (let j = 0; j < 8; j++) c = (c >>> 1) ^ (0xedb88320 & -(c & 1)); } return (~c) >>> 0; }
function makeSeedPng(w, h, [r, g, b]) {
  const raw = Buffer.alloc((w * 3 + 1) * h);
  for (let y = 0; y < h; y++) { const rs = y * (w * 3 + 1); raw[rs] = 0; for (let x = 0; x < w; x++) { const p = rs + 1 + x * 3; raw[p] = r; raw[p + 1] = g; raw[p + 2] = b; } }
  const idat = zlib.deflateSync(raw);
  const chunk = (t, d) => { const l = Buffer.alloc(4); l.writeUInt32BE(d.length, 0); const tb = Buffer.from(t, 'ascii'); const cb = Buffer.alloc(4); cb.writeUInt32BE(crc32(Buffer.concat([tb, d])), 0); return Buffer.concat([l, tb, d, cb]); };
  const ihdr = Buffer.alloc(13); ihdr.writeUInt32BE(w, 0); ihdr.writeUInt32BE(h, 4); ihdr[8] = 8; ihdr[9] = 2;
  return Buffer.concat([Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]), chunk('IHDR', ihdr), chunk('IDAT', idat), chunk('IEND', Buffer.alloc(0))]);
}
